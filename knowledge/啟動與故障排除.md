# 啟動方式與故障排除

7L 系統的啟動順序、常見故障與對應解法。維運時先查這份。

## 正常啟動順序

1. 開啟 **VTube Studio**：設定 → Plugins → 確認 **API 已啟用、Port 8001**（若沒勾，7L 會一直連不上 `ws://127.0.0.1:8001`）。
2. 雙擊 **`V7.bat`**：會自動背景啟動 CosyVoice 本地 TTS 服務（載入約 25~60 秒），期間語音自動用 kokoro 頂著，就緒後第一次合成會自己切過去。
3. 瀏覽器開 **`http://localhost:7860`** 看控制台（控制台只綁本機回環；要讓別台機器連需設 `WEB_BIND_HOST=0.0.0.0`，不建議）。

## 常見故障

### VTS 連不上 / 一直重連
- 確認 VTube Studio 開著，且設定 → Plugins → API 啟用（Port 8001）。
- 若日誌出現 `token is invalid or has been revoked`：執行 `python scripts/claim_vts_token.py --timeout 300`，然後到 VTS 彈窗按【允許】；成功會寫入 `vts_token.txt`，之後啟動免按。
- 重領前若卡在「認證視窗還開著」，先到 VTS 把那個彈窗按掉（或重啟 VTS）再跑腳本。

### 語音沒有出來 / 聲音變慢
- CosyVoice 服務沒開時會自動降級 kokoro，屬正常；要確認健康狀態：`http://127.0.0.1:9881/health` 是否 `ok:true`。
- 手動起服務：`powershell -ExecutionPolicy Bypass -File scripts\start_cosyvoice.ps1`。
- 服務日誌：專案根目錄的 `cosyvoice_service.log` / `.err.log`。
- 中文唸起來怪（像別的方言）：kokoro 必須走 misaki `version=1.1` 前端（注音+數字調），已修正於 commit 57fee7b；若回歸就是誤用 espeak 路徑。

### Groq 文字沒反應
- 金鑰在 `.env` 的 `GROQ_API_KEYS`（目前 30 把，逗號分隔），限流 `GROQ_REQUESTS_PER_MINUTE`（目前 20）。
- 模型 404 會被啟動時的 `/models` 交叉驗證自動過濾，不用手改梯隊。
- 只有 3 個可對話模型：`qwen/qwen3.8-27b`、`openai/gpt-oss-120b`、`openai/gpt-oss-20b`（`allam-2-7b` 為墊底）。

### ElevenLabs（可選引擎）
- 免費版每月 10,000 字元；`.env` 設 `ELEVENLABS_API_KEY`，用 `TTS_ENGINE=elevenlabs` 才會啟用。
- 額度用盡會自動拋錯降級本地引擎，不會中斷直播。

### RAG 撈不到東西
- 向量庫在 `data/rag/chroma`；新增知識檔放 `knowledge/` 後執行 `python scripts/ingest_rag.py --source knowledge`。
- 記憶類來源：`python scripts/ingest_rag.py --source memory`。
- 嵌入模型必須建檔與查詢一致（本地 fastembed `BAAI/bge-small-zh-v1.5`）。

## 環境要點

- Python 3.11，PyTorch 2.6.0+cu124（RTX 3060 Ti 8GB）。
- CosyVoice 用獨立環境 `venvs/cosyvoice`（依賴釘選與主專案衝突，絕不可裝進系統環境）。
- wetext 文字正規化 FST 必須放純 ASCII 路徑 `%USERPROFILE%\.cache\7l_wetext`（kaldisft 的 C++ 開檔吃不了中文路徑），重建用 `scripts/download_wetext.ps1`。
- 模型檔：`models/`（Kokoro 約 360MB、CosyVoice 約 9.3GB），皆不入 git，用 `scripts/download_kokoro.ps1` 等腳本重建。
